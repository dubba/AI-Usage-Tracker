# Repository guidance

This is a standalone Windows/macOS Tauri application. Keep account authentication, token refresh, quota retrieval, and secure storage inside the Rust backend. The React frontend must receive only sanitized account and usage data.

Before changing behavior:

1. Identify whether the change affects OAuth, credential storage, usage normalization, local API compatibility, or desktop packaging.
2. Keep the versioned local API backward-compatible whenever possible.
3. Never log or expose OAuth access tokens, refresh tokens, ID tokens, authorization codes, or raw OpenAI responses.
4. Do not add a secondary usage endpoint without an explicit product decision.
5. Do not introduce dependencies on external coding CLIs.

Changelog:

- Read `docs/CHANGELOG_WORKFLOW.md` before completing a pull request.
- Every user-visible change must update `CHANGELOG.md` under `## Unreleased` in the same pull request.
- Always keep item counts up to date in parentheses next to each category header (e.g. `### Security (4)`) and total items next to the release header (e.g. `## Unreleased (111 items)`).
- When there is no user-facing change, leave `CHANGELOG.md` unchanged and state `No user-facing change` in the pull request description.

Android APK & iOS SideStore builds:

- Do not build a new APK or iOS build automatically; only build when explicitly instructed by the user.
- When asked to build an APK containing code for an unreleased version, increment the latest release version by `0.0.1` and append `-unrel` to the version number (e.g. if the latest release on GitHub is `0.3.5`, name the APK `AI Usage Tracker_0.3.6-unrel.apk`).
- Android builds ship arm64-v8a only (`abiFilters` in `src-tauri/gen/android/app/build.gradle.kts`; CI also passes `--target aarch64`). Use `npm run android:build` (APK) or `npm run android:dev` (emulator). Never run `cargo tauri android build` without `--target aarch64`: the other ABIs are dropped at packaging, so compiling them only wastes time. Do not suggest `cargo clean` casually (~8G build cache; full recompile is very slow).
- Release IPAs are built unsigned by GitHub Actions (`.github/workflows/build-ios.yml`). Xcode is installed locally on the external drive (`/Volumes/External/Applications/Xcode.app`) with the iOS 27 simulator, for testing only:
  - Build a simulator app that loads its pages the way release builds do (`tauri ios dev` loads them from the dev server instead, so app-origin bugs do not show there): `npx tauri ios build --target aarch64-sim --debug --no-sign --archive-only`, then install `src-tauri/gen/apple/build/ai-usage-tracker_iOS.xcarchive/Products/Applications/AI Usage Tracker.app`.
  - The build rewrites `src-tauri/gen/apple/ai-usage-tracker_iOS/Info.plist` (version and merged `Info.ios.plist` keys); restore it with `git checkout` before committing.
  - Keep `~/Library/Developer/CoreSimulator` on the internal disk (about 200 MB). Symlinked to the external drive, the simulator service cannot write there and lists no devices.
  - The debug build takes about 10 seconds to become responsive; taps before then do nothing.
  - Apps built with the iOS 27 SDK must use the scene life cycle. That needs Tauri 2.12 or later and the `UIApplicationSceneManifest` key in `src-tauri/Info.ios.plist`; without them the app refuses to launch.
- Automated multi-platform releases run via `.github/workflows/build-installers.yml`: every platform (Windows, Android, macOS desktop, and the iOS SideStore IPA) builds on both Thursdays and Sundays at 11:45 PM US Eastern, winter and summer alike (the `schedule` entries set `timezone: America/New_York`, so GitHub follows daylight saving time; the start is kept off the top of the hour, and scheduled runs can still start late). The repo is public, so runner minutes are free, and each release must be complete because the in-app updater reads `releases/latest`. A pre-flight `check-changes` job checks whether new commits exist since the latest release tag and skips execution if none were committed, preserving GitHub runner quota (the pipeline's own `chore(release): bump version` and `chore: update SideStore source` commits do not count). Versions are numbered from the tags: if the version in `package.json` is already tagged, the run releases the next unreleased stable patch (0.4.1 -> 0.4.2) and the `commit-version-bump` job writes it back to the version files on `main` and renames `## Unreleased` in `CHANGELOG.md` to `## <version> - <date> (N items)` and opens a new empty `## Unreleased (0 items)` above it (US Eastern standard date; pre-release versions leave Unreleased alone). To ship a specific version or a beta, set it in `package.json`; an untagged version, including `-beta.N`, releases exactly as written. The release page body is generated by the last job (`release-notes`) from `CHANGELOG.md` and `.github/release-notes/download-guide.md` via `scripts/release-notes.mjs`; edit the guide file, not the workflow, to change the download instructions.
- `src-tauri/gen/apple` is generated on a macOS runner by the manual "Generate iOS project" workflow (`.github/workflows/init-ios-project.yml`), which commits it. Re-run it after a Tauri CLI upgrade or a bundle ID / `Info.ios.plist` change and review the diff. `tauri ios init` can run locally now that Xcode is installed, but use the workflow so the committed project is always generated the same way.
- SideStore source manifest is at `sidestore-source.json`. Use `npm run update:sidestore` (`node scripts/update-sidestore-source.mjs`) to refresh release asset sizes and URLs.
- Gradle needs the Homebrew JDK. `npm run android:dev` / `android:build` already set `JAVA_HOME` to `/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home`. If you invoke Gradle or `tauri android` directly, export that same `JAVA_HOME` first.

Security audits:

- Follow `docs/AUDIT_PROTOCOL.md` when asked to audit or review the app. Audits are read-only, every claim needs `file:line` evidence, and reports go in the gitignored `.audits/` directory, never into the repository.
- `docs/THREAT_MODEL.md` is the Pass 0 inventory of assets, entry points, and the code that guards them. Update it whenever you add an entry point (a new command, listener, WebView, deep link, provider endpoint, or file the app writes).
- For every change, identify which trust boundary it touches (see Pass 0 of the protocol), validate arguments on the Rust side, and add a negative test for each security check you add.

Validation:

```bash
npm run check
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
cargo check --manifest-path src-tauri/Cargo.toml
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
```

Do not run these by hand before every commit, and never after every edit: the `pre-push` hook runs them all once, through `npm run preflight` (below), when commits are pushed. Commit freely; if preflight fails on push, fix it in a follow-up commit and push again. Any Rust edit recompiles the whole `ai-usage-tracker` crate, so each of `cargo clippy`, `cargo test`, and a mobile `cargo check` is a separate build of about 1.5 to 3 minutes, and stacking them after small edits adds up fast. While iterating, run only the one check that can catch a mistake in what changed: the touched module's tests (`cargo test --manifest-path src-tauri/Cargo.toml --lib <module>`), or `cargo check --manifest-path src-tauri/Cargo.toml --lib --target aarch64-apple-ios-sim` for `cfg(mobile)` code, which desktop clippy and tests never compile.

`npm run preflight` runs the CI-equivalent checks (npm steps, fmt, clippy debug and release, `cargo test --lib`, Android compile, `npm audit`, `cargo audit`) in a throwaway worktree of `HEAD`, so gitignored generated files cannot hide a failure that CI would catch. It takes about 2 minutes warm and about 9 cold, and keeps its caches (about 5 GB) under `/Volumes/External/_caches` when that drive is mounted, otherwise `~/.cache`; override with `PREFLIGHT_CACHE_DIR`. It skips the iOS compile without full Xcode, and cannot cover the Windows job. `npm run hooks:install` points `core.hooksPath` at `.githooks` so it also runs before every `git push`; use `git push --no-verify` to bypass.

The full test inventory and the security-invariant → test map live in `TESTING.md`. CI runs `npm test` and the `npm run test:*` scripts in the `validate/frontend` job; run them locally before pushing anyway.
